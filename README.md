## Тестирование
1. Создать базу `agromarket_test` (pgAdmin)
2. Скопировать `.env` в `.env.test` и указать в нём тестовую базу
3. `npm test` — все тесты, `npm run test:watch` — режим наблюдения,
   `npm run coverage` — отчёт о покрытии (сейчас: Lines ...%)

## Правила работы с Git
- Ветка `main` защищена: изменения только через Pull Request
- PR сливается после зелёного CI и одобрения ревьюера
- Ветки: `feature/...`, `fix/...`; коммиты: feat, fix, test, refactor, docs, ci, chore

## Переменные окружения (.env)
JWT_SECRET      — случайная строка 64 символа
JWT_EXPIRES_IN  — срок жизни токена, например 2h
ADMIN_EMAIL / ADMIN_PASSWORD — администратор, создаётся командой npm run db:init

## Лабораторная 7 — ответы
- Одинаковые ли хэши у двух пользователей с одним паролем и почему: нет, разные, потому что bcrypt добавляет к паролю случайную соль и хранит её в хэше.
- Что вернул сервер на регистрацию с "role": "admin": 201 с ролью user, так как роль из тела запроса не читается (защита от mass assignment).
- Почему подделанный на jwt.io токен не прошёл: подпись считается из заголовка и данных с секретным ключом. После изменения роли подпись не сходится, а новую без JWT_SECRET посчитать нельзя.
- Что произошло после порчи токена в localStorage: /auth/me вернул 401, apiFetch удалил token и user и перезагрузил страницу, снова показана форма входа.
- Почему спрятать кнопку в React недостаточно: клиентский код можно обойти (запрос из консоли, Postman), настоящая защита это requireAuth и requireRole на сервере.
- Использовал(а) ли ИИ и для чего: для анализа ошибок
